<br/>

[![CI](https://github.com/amjadh27/Netops-pipeline/actions/workflows/ci.yml/badge.svg)](https://github.com/amjadh27/Netops-pipeline/actions)
![Stack](https://img.shields.io/badge/stack-NetBox%20%7C%20Ansible%20%7C%20containerlab%20%7C%20FRR%20%7C%20Batfish-2E75B6)
![Status](https://img.shields.io/badge/status-complete-2E7D32)

A **source-of-truth network automation pipeline** that turns modelled intent into deployed, validated network state. NetBox holds the truth, Ansible renders configs, containerlab runs four FRR routers across two autonomous systems (OSPF + iBGP + eBGP), Batfish validates routing offline, and GitHub Actions gates every change.

### What it demonstrates

🧠 **Intent modelling** — NetBox as the single source of truth for sites, devices, IPs, ASNs
⚙️ **Idempotent automation** — Ansible renders from intent; a second run reports no change
🌐 **Multi-protocol routing** — OSPF, iBGP, and eBGP working together across two sites
🔍 **Verification, not hope** — Batfish offline checks + live route validation + CI drift gating
📋 **Production discipline** — 14 real issues encountered and documented with fixes

### Highlights

- 🟢 **CI passing** — every push is linted, rendered, diffed against reference configs, and Batfish-validated
- 📊 **5/5 Batfish checks** and **7/7 live validation checks** green
- 📐 **Byte-for-byte match** between template-rendered and hand-built reference configs
- 📚 **Comprehensive documentation** — 16-page report, modern README with Mermaid diagrams, full troubleshooting log

🔗 **[Explore the repo →](https://github.com/amjadh27/Netops-pipeline)**

## 🔬 Current Research

### Adaptive Flow Admission for SDN Flow-Table Overflow Attacks

Moving SDN switches from **reactive attack handling** to **proactive admission control** using reinforcement learning. Controller-side signals (flow-table occupancy, Packet-In pressure, suspicion indicators) feed an RL agent that decides which flows to admit before the table fills.

**Testbed:** `Mininet` · `Open vSwitch` · `OpenFlow` · `POX` · `Ryu` · `Python` · `Pandas` · `Matplotlib`

**Evaluation scenarios:** normal traffic · flash-crowd · low-rate flow-table overflow (LFTO) · mixed
**Metrics:** flow-table occupancy · Packet-In rate · benign drop rate · attack drop rate · throughput · latency · controller burden

> 🎯 The goal isn't just attack mitigation — it's making the trade-off between security and benign traffic impact *measurable and tunable*.
